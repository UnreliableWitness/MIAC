# Tasks across repos (brainstorm, issue #48)

Date: 2026-10-16. Status: **proposal, nothing decided**. The owner picks an approach and answers the open questions at the end; a design spec follows from that.

## Problem

A task is one repo, one branch, one worktree. Two things go wrong in practice:
- **(a) Wrong repo.** The task was started in repo X but the change belongs in repo Y. Today the only way out is Finish (or Cancel) and start again, which loses the Claude conversation and splits the AI cost over two tasks.
- **(b) Several repos.** One work item needs changes in 2 or 3 repos (for example an API, a web app and a shared package). Today that means one task per repo, each with its own Claude that cannot see the other repos.

A likely cause of (a): the Sprint page's Start uses the **first** repo linked to the project's connection (`SprintScreen.tsx`, `repos.find((r) => r.connectionId === connectionId)`). With several repos on one connection, Start silently picks one.

## What assumes one repo per task today

| Area | Where | Assumption |
|---|---|---|
| Model | `TaskSchema` in `src/shared/types.ts` | One `repoId`, `branch`, `worktreePath`, `baseRef`, `baseSha`, `summary`, `pullRequest`, `reopen`. |
| Create | `tasks:create` in `handlers.ts` | Branch and folder uniqueness checked per repo; worktree at `<repo>.worktrees/<slug>` (`worktreeRoot`). |
| Setup | `SetupRunner.ts`, `SetupPlan` | One plan: fetch, worktree, work item, copy, `.miac/task.md`, commands, terminals, all for one repo. `.miac/` excluded in that repo's `.git/info/exclude`. |
| `.miac.yml` | `MiacConfig.ts` | Read from the one repo: base, branch template, copy, setup, run. |
| Connection | `repo.connectionId` | The work item, usage write-back, PR target and Sprint status all go through the task's repo's connection. |
| Terminals | `spawnTerminal` | Every tab's cwd is `task.worktreePath`. |
| Claude | `claudeContext`, `claudeSessions.ts` | "This folder is a MIAC task…", details in `.miac/task.md`. Sessions are saved per cwd (`~/.claude/projects/<cwd>/`); `--resume <id>` and `--continue` depend on the cwd staying the same. |
| Docs tab | `docsHandlers.ts`, `DocsWatcher` | Lists and watches one worktree; new/modified badges against the one `baseSha`. |
| Terminal links | `terminalLinks.ts` | `path:line` resolves inside the one worktree. |
| Header | `HeaderBar.tsx`, `useGitSummary` | One repo in the breadcrumb, one worktree path, one ahead/behind. |
| Nav | `TaskNav.groupTasks` | Tasks grouped under their one repo. |
| Sprint page | `taskFor` | A row finds its task by work item id plus the repo's connection. |
| Usage | `telemetryEnv`, `UsageStore`, `UsageSync` | Keyed by **task id**, not repo. `Custom.AI*` fields are **set** to the task's totals, so two tasks on one work item overwrite each other (last write wins). |
| Finish | `tasks:finish`, `FinishScreen` | One finish check, one summary, one push, one PR, one worktree and branch removed. PR choice remembered per repo. |
| Reopen | `tasks:reopen` | Restores one worktree from branch, `origin/<branch>`, last commit or base. |
| Done page | `DoneTaskPage.tsx` | One changes/commits block, one PR with live status. |

Good news: **cost tracking is already per task, not per repo**. Any approach that keeps one task per work item keeps cost, write-back and the usage comment as they are.

## Approaches

### A. One task, a list of worktrees, Claude in the first repo

The task gets `worktrees: [{ repoId, branch, path, baseRef, baseSha, summary, pullRequest }]`. Worktrees stay where they are today (`<repo>.worktrees/<slug>`). Each terminal is bound to one worktree (its cwd). Claude starts in the first repo's worktree and sees the others through `--add-dir`.

- Setup: the pipeline runs once per repo (its own fetch, worktree, copy, commands from its `.miac.yml`); the work item step runs once.
- Claude: keeps today's single-repo behaviour (git context, the repo's CLAUDE.md). Other repos' CLAUDE.md files are not loaded by `--add-dir` by default. `--add-dir` must be passed again on every resume.
- Wrong repo (a): weak. Removing the first repo removes the folder Claude runs in, so its session can no longer be resumed from there (sessions are saved per cwd; to verify). In practice you keep the wrong repo as an empty "home".
- Old tasks: fit as a list of one, no migration of folders.
- Effort: medium.

### B. One task folder holding the worktrees side by side (recommended)

Each task gets its own folder, and every repo's worktree lives inside it:

```
<tasks root>/1234-fix-login/
  CLAUDE.md          generated by MIAC: the task, the repos and branches, @imports of each repo's CLAUDE.md
  .miac/task.md
  api/               git worktree of repo "api", branch feature/1234-fix-login
  web/               git worktree of repo "web", same branch name
```

The model is the same list of worktrees as in A, plus `folder`. Claude (and Copilot) start in the task folder and see every repo as a subfolder. Shell and run tabs are bound to one repo's worktree.

- Setup: as A, per repo. `.miac/` sits outside every repo, so no `.git/info/exclude` entry is needed for new tasks.
- Claude: one conversation over all repos. Its cwd never changes during the task, so adding or removing a repo never breaks `--resume`. The generated `CLAUDE.md` keeps each repo's instructions loaded (`@api/CLAUDE.md`). Cost: Claude starts outside a git repo, so it loses the git status it gets at start; the context lists the repos and branches instead.
- Wrong repo (a): **Add repo** Y, then **Remove repo** X. The conversation, the cost and the work item stay. A single "Move to another repo" button can do both when X has no commits.
- Old tasks: their folder is their worktree, so they cannot take a second repo without moving; keep them single-repo.
- Effort: medium-large (new folder location, generated CLAUDE.md, per-repo Finish/Reopen/Done).

### C. Separate tasks per repo, grouped by work item, plus "Move task"

Keep one repo per task. Allow several tasks for one work item, show them together, and add "Move to another repo" (new worktree in Y, old one removed, Claude started again).

- Least model change.
- Cost: needs new work: the `Custom.AI*` fields must be summed over all tasks of the work item, or they overwrite each other; one usage comment per task.
- Claude: one per repo, none sees the whole change. A move loses the conversation (different cwd).
- Sprint page, nav and Done page must learn "a work item has several tasks".
- Effort: small for the move, then grows with every place that has to group tasks.

### Side by side

| | A. List, Claude in first repo | B. Task folder | C. Task per repo |
|---|---|---|---|
| Claude sees all repos | Yes, via `--add-dir` | Yes, as subfolders | No |
| Claude survives a repo move | No (cwd goes) | Yes | No |
| Repo CLAUDE.md loaded | First repo only | All, via generated imports | Each in its own task |
| Git status in Claude's start context | Yes | No | Yes |
| Cost and write-back | Unchanged | Unchanged | Needs summing per work item |
| Finish: one PR per repo | Yes | Yes | Yes (one per task) |
| Old tasks | Fit as is | Stay single-repo | Fit as is |
| Effort | Medium | Medium-large | Small, then grows |

## Recommendation

**B, in three steps**, each shippable on its own:

1. **Pick the repo on Start** (fixes most of (a), independent of the rest). When a connection has more than one repo, the Sprint page's Start asks which repo(s), preselecting the last one used for that project. New task gets the same picker.
2. **Task folder and Add repo.** New tasks get a task folder; a ready task can **Add repo** (runs that repo's setup only, while the other terminals keep running) and **Remove repo** (refused when it has commits or uncommitted changes, unless confirmed). This covers (a) fully and (b) for repos found out along the way.
3. **Finish, Reopen and Done per repo.** Finish checks each repo, takes a summary per repo, makes one draft PR per repo that has commits, all linked to the same work item. Reopen restores each worktree with today's rules. Done shows one block per repo and the cost once.

Choosing several repos at start (a multi-select in New task) comes for free once step 2 exists.

## How B works per area

- **Model.** `Task.worktrees[]` with per-repo `repoId`, `branch`, `path`, `baseRef`, `baseSha`, `summary`, `pullRequest`, `reopen`, `status` (setting-up, ready, setup-failed). `Task.folder`. `TerminalDef.repoId` (absent = task folder). Old tasks load as one entry with `folder = worktreePath`.
- **Branch name.** The same branch name in every repo (from the first repo's `.miac.yml` template), so the PRs are easy to match.
- **Setup.** The setup page shows a group of steps per repo. A failed repo can be retried or removed without touching the others. The work item step runs once, at the first repo.
- **`.miac.yml`.** Stays per repo. Copy, setup and run commands run in that repo's worktree. Run tabs are labelled with the repo when the task has more than one.
- **Terminals.** The + menu asks for a repo for shell and run tabs when there are several; Claude, Copilot and OpenCode open in the task folder. `path:line` links resolve against the tab's cwd.
- **Claude context.** `claudeContext` and `CLAUDE.md` list the repos, their folders and branches, and say which repo each change belongs in. Adding a repo rewrites `CLAUDE.md`; a running Claude is told nothing until its next start, unless we paste a short note into it (open question).
- **Docs tab.** Lists the whole task folder grouped by repo; badges per repo against that repo's `baseSha`.
- **Header and nav.** Breadcrumb shows the first repo and "+2"; the header's git line shows one ahead/behind per repo. The nav groups the task under its first repo.
- **Cost.** Unchanged: one task id, one work item, one set of `Custom.AI*` values, one usage comment.
- **Finish.** Per repo: uncommitted and unpushed checks, a "Create draft PR" tick (on by default for repos with commits). Each PR description lists the other PRs of the task. If one PR fails, the ones made stay, cleanup waits, and Retry continues with the rest.
- **Reopen.** Each worktree is restored with today's rules; Claude resumes in the task folder.
- **Done page.** A section per repo (changes, commits, PR status), duration and cost once.

## Open questions (with suggested defaults)

1. **Approach.** A, B or C? *Default: B.*
2. **Start picker.** When a connection has several repos, should Start ask every time, or use the last repo for that project and show it on the button ("Start in api")? *Default: use the last one, with a dropdown on the button to change it.*
3. **Where do task folders live?** *Default: a setting "Tasks folder", default `~/miac/tasks` (`%USERPROFILE%\miac\tasks` on Windows); slugs stay short for Windows path length.*
4. **Single-repo tasks: task folder too?** Means Claude always starts one level above the repo. *Default: yes, for one model; the generated `CLAUDE.md` imports the repo's instructions.*
5. **Repos from another Azure DevOps connection.** Allow a repo whose connection differs from the work item's? Its PR could not be linked to the work item. *Default: only repos on the same connection (or with none, then no PR for that repo).*
6. **Removing a repo with commits.** *Default: allowed after a confirm that names the commit count; the branch is kept unless "delete branch" is ticked.*
7. **Telling a running Claude about an added repo.** *Default: paste a one-line note into each Claude tab without Enter (like Send to), so the user decides when to send it.*
8. **Branch name across repos.** Same name everywhere, or each repo's own `.miac.yml` template? *Default: same name, from the first repo's template.*
9. **Repo groups.** Should `.miac.yml` (or Settings) list repos that usually go together, to preselect them? *Default: not now; add it if people keep picking the same set.*
10. **Old tasks.** Leave tasks made before this change single-repo? *Default: yes.*
