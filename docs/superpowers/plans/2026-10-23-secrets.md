# Secrets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Secrets are discovered on this machine, imported through a friendly screen, stored encrypted per developer, injected per task environment only into Setup / dev-server / test / the user's shell tabs, reachable for agents only through `shellie run <name>`, and watched for leaks.

**Architecture:** Main owns everything that touches values: `src/main/secrets/` (store, discovery, injection, matcher, run endpoint). The renderer only sees masked values and names, plus a held reveal. The task gains an `environment`; `spawnTerminal` adds `secretsEnv` for non-agent tabs; the existing local receiver (127.0.0.1:receiverPort, today `/v1/attention`) gains `/v1/run` for `shellie run`, called by a small generated shim on agent tabs' PATH.

**Tech Stack:** Electron (`safeStorage` via the existing `TokenCrypto`), React, TypeScript, zod, Vitest + Testing Library, oxlint/oxfmt. Branch `feature/secrets` (worktree in the session scratchpad; holds the spec and mockups).

**Spec:** `docs/superpowers/specs/2026-10-23-secrets-design.md` (mockups `design/mockups/secrets/`; 4 and 5 supersede 2).

## Global Constraints

- Environments are exactly `development | test | uat | production`, displayed Development, Test, UAT, Production.
- Values are decrypted in main only. The renderer gets masks; a full value only through `secrets:reveal` while held, never stored in renderer state after release. No value, name, path or source in telemetry, logs, crash reports.
- Agent kinds `claude`, `copilot`, `opencode` never receive secret env. `shellie run` accepts only named commands (repo `run:` names, `test`, `setup`); never a shell line.
- UAT and Production: confirm before every switch and every `shellie run`; band amber (UAT) / red (Production); Production expires after `secrets.productionMinutes` (default 60) and always at Finish; Start never picks them.
- Shellie never edits git-tracked files, and edits the developer's own main-checkout files only on an explicit tick (`.env`-style files only).
- With no secrets stored, every task behaves exactly as today.
- All shell/path logic behind `Platform`; Windows is the release target. Every commit passes `npm test`, `npm run typecheck`, `npm run lint`.
- Commit messages end with the session's attribution lines.

## Review Focus

1. A value containing `=`, quotes, `#`, newlines or `$` (connection strings, PEM keys) survives discovery → store → env injection unchanged (Task 2, Task 3).
2. `shellie run` while Shellie is closed, or with a stale token after a relaunch: the shim prints a clear "Shellie is not running" / "this task's run link expired" and exits 1, never hangs (Task 8).
3. A secret value split across two pty chunks in agent output is still masked (Task 7).
4. A repo with only a plain `.env` of non-secrets: import shows nothing ticked, the status panel says nothing to protect, tasks unchanged (Task 5, Task 10).
5. Production expiry while a `shellie run` is in flight: the run is stopped and the agent gets a clear message and exit code (Task 6 calls the hook, Task 8 stops the run; Task 8 tests that a stopped run ends the shim with "Production ended" and exit 1).
